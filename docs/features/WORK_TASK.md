# Work task presentation — phase2

Private source references show a submitted Work task, Working/Stopped working labels, an inline status-detail expansion, a task overflow menu, an empty Uploaded files Library sheet, and clarification cards 1 and 2 of 3. Exact animation timing, all answer-result behavior, third question, successful task completion and populated library are not established.

`WorkTaskPresentationState` owns local carousel position, answer drafts, selected answers, expansion and follow-up draft. Hosts supply messages, status, questions/options and activity text. Empty defaults contain no fabricated task response. Typed `WorkTaskAction` events delegate Stop, answer/skip, follow-up and uncaptured menu destinations. Stop is idempotent while pending and never changes runtime status; hosts update it. If the host rejects/cancels a stop request while still working, `resolveStopRequest()` clears the pending latch without changing status. Answers do not automatically advance or pretend to finish a task. Local selection retention and a Send label for nonempty freeform answers are provisional until source aftermath is captured.

`WorkTaskView(state:onBack:)` uses SwiftUI native Menu, sheets, text fields, glass surfaces and safe-area layout. Status details expand inline; no invented activity sheet. The observed empty Uploaded files view is implemented; optional uploadedFilesContent lets a host supply a populated library. Share/Pin/Add to project/Find/Archive/Delete remain host intents; the Add to project submenu contents and destructive confirmations are unobserved. Host callbacks must supply those interfaces; an event is not counted as destination fidelity.

Apple's [model-data guidance](https://developer.apple.com/documentation/SwiftUI/Model-data) supplies the Observable/Bindable pattern. The bottom composer/question card uses [safeAreaInset](https://developer.apple.com/documentation/swiftui/view/safeareainset(edge:alignment:spacing:content:)-6gwby) so system keyboard safe areas participate in layout. Exact source fonts, glyphs, materials and transition curves remain subject to rendered comparison.

All nine passed within the integrated 143-test suite (`chatgpt-phase2-final-state.log`), including host Stop-request retry. It exercised Stop, question navigation with retained typed draft, closing questions, inline status detail and opening/closing Library. The first-card, inline-trace and Library screenshots were individually inspected: expected controls/text are present and unclipped. Exact metrics/glyphs/materials and all state combinations are not certified.

Earlier UI attempts exposed a parent accessibility identifier overriding the child controls and a test selecting TextView instead of the actual native TextField. The unused parent IDs were removed, child IDs preserved, and the corrected native-field query passed.

Host updates preserve current question identity and drafts while the card is open, prune removed questions/options, and close it when no questions remain. Newly supplied questions after dismissal remain hidden until `showClarification()` is called. Overflow actions are typed intents; Archive/Delete do not mutate task data. No custom animation or timers are attached to these views. Native sheets/menus use system transitions; Reduce Motion and VoiceOver traversal have not been exercised, so no accessibility/motion-parity certification is claimed. Fixed font sizes follow the captured baseline; Dynamic Type layout needs separate validation.
