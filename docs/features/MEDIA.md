# Image presentation and host integration

`ChatMedia` is immutable metadata: a UUID, opaque image key, accessibility title and positive finite aspect ratio (invalid ratios fall back to 1). The key is not fetched or opened by the package. Supply images through the root's `mediaImageProvider`, or directly through `MediaViewer(state:imageProvider:)`. Resolved image dimensions determine the viewer's intrinsic aspect-fit rendering; metadata ratio is available for thumbnails and host layout.

`MediaViewerState` owns the active item, local favorite and visible controls. `present` emits `.open`, and `dismiss` emits `.close` once. A new presentation resets transient hidden controls. Actions carrying another image's ID are ignored, which prevents a dismissed menu from affecting the next image. The host receives copy, download, edit, resize and remove intents; none writes a file or reports a completed edit. **Remove is the observed eraser tool**, not a delete-file operation.

The full-screen viewer is shared with Space. It centers the image in the complete viewport and overlays controls; tapping the image hides or shows every control without moving the image. The status bar stays hidden in both observed modes. The native menu offers Add to Favorites; the reversible Remove from Favorites state is local skeleton behavior whose original appearance is not yet captured. Space retains its captured filename menu caption; chat's menu has no caption. Edit, Resize and Remove remain typed host requests because their destination layouts were not inspected.

Recent-photo content is host supplied. No Photos permission, camera, network or clipboard-image export occurs automatically. The demo uses fictional media. Never supply private evidence captures as public fixtures.

Source stills establish a roughly 185 × 191-point sent image and a roughly 211 × 216-point Copy-only hold preview. These are reference measurements, not exact motion timing; native context-menu animation is used. Full-screen stills establish chrome, favorite menu and unchanged hidden-controls image placement. Exact vendor icon artwork, editing outcomes, all aspect-ratio variants, pinch gestures and transition timing remain gaps.

The implementation uses [Apple aspect-fit rendering](https://developer.apple.com/documentation/swiftui/view/aspectratio(_:contentmode:)), [status-bar control](https://developer.apple.com/documentation/swiftui/view/statusbarhidden(_:)) and native SwiftUI menus. Six state tests cover invalid dimensions, empty presentation, reset/dismiss, favorite idempotency, stale IDs and intent-only modifications. Integrated rendering and shared-Space regression results are recorded by the app validation run.

## Video branch

`ChatMedia(kind: .video, durationSeconds: 8, …)` distinguishes a movie from an image while retaining the same stable ID and opaque preview key. Duration is explicit host data: negative values become unknown; the UI does not derive rounding from the 9-second gallery clip versus 0:08 composer reference. Image metadata discards duration. `MediaViewer` accepts an optional `(ChatMedia) -> AnyView?` video provider for host-owned moving content. Without it, the image provider can supply a poster; that fallback does not pretend playback is occurring. The root forwards the same closure.

Full-screen videos show only the captured Close and Fit controls and retain the system status bar. Image-only favorites, download and editing controls are absent, and movie taps do not borrow the image hide-controls behavior. The Fit button emits `.requestVideoFit(id)`; its visual result was not confirmed in the source, so no crop/zoom result is manufactured. Hosts can implement playback with [Apple AVPlayerLayer and videoGravity](https://developer.apple.com/documentation/avfoundation/avplayerlayer/videogravity); a stock [VideoPlayer](https://developer.apple.com/documentation/avkit/videoplayer) supplies transport controls, but those controls have not been observed in these references. Player/audio lifecycle and looping remain host responsibilities.

The source collector observed auto-looping, but no loop timing, timeline, play/pause UI or audio behavior was measured. `chatgpt-video-player-controls.png` is only a tapped movie frame. The Dot call controls inside that movie are recorded pixels, not viewer actions. A subsequent complete sent-card reference resolves the clipped geometry: approximately 120×240pt, 14pt rounded corners and a centered 40pt white outlined Play circle. Tapping or holding that paused card opens the viewer; no image Copy menu was observed. This is one portrait clip, not a universal maximum or proof of autoplay policy. Four video state tests cover legacy image behavior, duration boundaries, intent guards and switching kinds without leaking image state.

## Sent-video presentation

`chat.videoCardPresentations[id]` is caller-owned `.pausedPoster` or `.hostPreview` state. The default paused poster shows Play. The preview case uses the supplied moving-content closure when available and hides the affordance; the package neither starts playback nor changes this flag on navigation. Missing moving content retains the supplied poster. The same card button opens the full-screen viewer in either state. Retiring turns and starting a new chat clear obsolete card presentation values.

The observed portrait card is 120pt wide and capped at 240pt high with 14pt corners. Other aspect ratios use their supplied ratio within that reference-derived layout bound; those variants are not source-verified. Full-screen Fit still emits only a host intent because a matching portrait ratio does not reveal its exact effect.

The updated paused-card simulator check passed in 17.081s: Play is exposed as a button, its visible and accessibility geometry is 120×240pt, tap and hold both open the video viewer, and no image Copy menu appears. The corresponding still-image regression passed in 27.012s with its 185pt width and Copy-only menu unchanged. The initial clipped image leaked 260pt into accessibility bounds despite a visible 240pt card; the final outer hit/accessibility element is explicitly bounded and retains the Button trait. The exact-source generic app/widget build also passed. The full pure suite contains 124 passing tests across 16 suites.
