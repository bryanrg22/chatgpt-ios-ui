# Rich-text presentation

`ChatGPTMarkdownView` renders `MarkdownDocumentModel` with SF typography, native text selection, quoted paragraphs, nested lists, dividers, code cards and GFM tables. Parsing uses the official [Swift Markdown](https://github.com/swiftlang/swift-markdown) package pinned to 0.9.0. The shared value-model adapter does not execute HTML, load remote images or run code. The included Apache-2.0 notice is `Swift-Markdown-LICENSE.txt`; this dependency license does not assign a license to the surrounding project.

The host handles `ChatAction.markdown` or the standalone view's `onAction`: code copy supplies the exact source string, links supply their destination, and unsupported/image content supplies typed metadata. Optional image/unsupported render closures can supply local views. The demo copies code locally and shows the tapped link in a local alert; this alert is a demo integration outcome, not a captured source-app destination.

The captured October 7 screens establish SF-style body/headings, a vertical quote bar, inline-code background, gray rounded code card, language header/copy glyph and separator-only tables. The implementation uses 17pt body text with 5pt extra line spacing, a 4pt quote bar and 24pt code corners as measured approximations. Font identity, exact metrics and external-link arrow treatment are not pixel-certified. Paragraphs/headings/list blocks and table cells with inline code now use a native selectable UITextView backed by TextKit: a NSLayoutManager draws rounded backgrounds per line, then UIKit paints selection above them. The 3pt corner radius and 1.5pt horizontal decoration are visual approximations, not measured source tokens. Copy contains the original text without inserted padding. Table cells preserve their declared left/center/right paragraph alignment and existing column widths; wide tables continue to scroll horizontally.

The small pure Python tokenizer preserves every source character and colors basic keywords, strings, f-string braces, numbers and comments. It is not a complete Python lexer or general language highlighter; unrecognized languages retain their unmodified source. Hosts may replace the renderer for wider syntax support. Long code scrolls horizontally. Copy changes to a checkmark with a provisional two-second reset. No expanded-code destination is claimed without a ChatGPT reference.

Selection is native and scoped to each rendered text block/cell/code block. Cross-block selection of an entire response is not yet implemented. System edit-menu actions vary by runtime. Parser tests cover nested formatting, escaped delimiters, lists, tables, code, links, images, unsupported HTML and partial streaming input; tokenizer tests cover exact source preservation and unknown-language fallback. The simulator code-copy confirmation, link action and native selection-menu test passed in 14.189s. Heading/list, code/table and real Copy/Share toolbar screenshots were inspected. Ordinary chat send/cancel/navigation also passed in 15.850s with the new renderer.

The October 8 bounded polish pass verifies nested inline-code detection and the unchanged parsed Unicode text. Dark/light simulator checks exercise wrapped pills, bold code, native Copy handles/menu, and a link within the same selectable paragraph; the ordinary Markdown code-copy/link/selection flow also passed. Dynamic Type, arbitrary host fonts, RTL and whole-response selection remain unverified. The implementation uses Apple’s public [NSLayoutManager background drawing](https://developer.apple.com/documentation/uikit/nslayoutmanager/drawbackground(forglyphrange:at:)) and UITextView selection APIs; it neither evaluates code nor opens links automatically.

Final bounded validation: 152 pure tests across 22 suites passed; the final inline-code dark/light UI test passed in 26.244s after line-edge clipping was corrected. Four final screenshots were individually inspected for rounded corners, wrapping, contrast, selection handles and the native menu. The existing Markdown code-copy/link/selection test passed in 14.516s, and the voice transcript/sharing/live-camera regression passed in 22.663s. The final generic simulator app and WidgetKit extension build passed. These are scoped checks, not a claim that every screen or every text layout matches the source app.

The captured Copy glyph uses SF Symbols `square.on.square`, with public UIImage horizontal orientation matching the foreground-square direction in the assistant action row and code header. Native text/image Copy menus show the correct unfolded silhouette and foreground tint, but UIKit normalizes that symbol’s orientation back to its default stack direction. That menu-direction difference remains TODO; no private menu override is used. Exact corner radius and stroke weight are still approximate. The camera Scan document glyph is separate and unchanged.
